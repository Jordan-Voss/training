# Architecture

Training uses Expo SDK 58, React Native, TypeScript and Expo Router. Expo development builds are required for SQLite, private camera/library files, Keychain storage and native video compression. Expo Router/React Native Web produce the website from the same components and domain logic. Vite bundles only the Cloudflare integration Worker and copies the Expo export; it does not provide a second frontend.

`packages/core/` has no platform or server credentials. It defines programme versions, ordered mesocycles, rounds, actual sessions, exercises, sets, activities, parsing, back-off calculation and durable operation semantics. `src/` owns local adapters, authenticated data access and UI. `services/integration/` owns Google and Garmin credentials, scoped sharing access and durable sheet jobs. Large videos travel directly from the client to Supabase Storage with TUS.

A mesocycle is the smallest complete non-repeating ordered sequence. Rounds repeat that sequence; calendar weeks do not advance it. A started session receives a new UUID and a deep copy of its prescription. Session IDs, set IDs, actual timestamps, local date/timezone and scheduled dates are independent. Accepted version rows are immutable; database triggers reject changes to the prescription of a started session. New versions change future session choices, preserving existing results. A rollover creates a different block identity.

Actual sets live in the session's JSON document in this first release, with stable exercise/set IDs. Sessions, versions, rounds, media, external activities, grants, source mappings, receipts and sheet jobs have relational owner constraints. This keeps an offline session save atomic without forcing every partially entered set through a separate request. Later analytics can add indexed projections without changing historical documents.

The native adapter stores the complete state and outbox in one SQLite transaction with WAL. The web adapter uses an IndexedDB transaction; it does not use SQLite's experimental browser adapter. Browser shell assets are cached for offline restarts. Cache entries exclude API responses and private media. Browser file blobs are stored separately in IndexedDB; on iPhone the original is copied into app documents before attaching it. A failed device save is displayed explicitly.

Every cloud operation carries a UUID and expected session revision. The database acquires a transaction lock, returns an existing receipt after uncertain success, rejects stale revisions, saves the session and writes its receipt in one transaction. Conflicts hold dependent operations; retries use bounded exponential backoff. Device saves, cloud saves, video uploads and sheet jobs have separate state. Demo data has its own storage scope and is never queued to the athlete's account.

Back-off targets use the verified source percentage and `MROUND(top × percentage, increment)`. The inspected sheet uses 2.5 kg increments. A missing top set stays missing. Pound inputs are converted to kilograms before applying the coach's rounding rule. Targets update on every valid top-weight edit. Copying a target into unlogged sets is an explicit action; completed actual loads stay intact.

The Google adapter uses immutable numeric sheet IDs and bounded ranges. It retains raw values, displayed text, formulas, number formats, validation and source notes. Date-formatted RPE ranges are flagged and retained verbatim. Slash-separated labels are not inferred to be complexes. Imported legacy top weights and notes remain source provenance, without fabricated sets or dates.

Google-owned input fingerprints exclude top-weight result cells, completion fields, derived formula results and Training's own marked athlete-note section. Other source notes remain protected. Before a result write, the Worker verifies the latest mapping record for that athlete/workbook/sheet, block generation, round, row label, coach fingerprint and destination values. Superseded jobs are held individually. Existing records are preserved. Google Sheets has no compare-and-swap for cell updates; a human can edit between the final read and atomic batch update. Production writeback stays disabled until an explicit operating/reconciliation procedure is accepted and tested on a copy.

Sheet jobs live in Postgres, have idempotency keys, ordered claims, retry times, leases and reconciliation after uncertain responses. Only top-set and athlete-note cells are written, using `updateCells.fields = userEnteredValue`. Formula, validation, formatting, completion and session-RPE cells are never result destinations. Read-only Google credentials and optional write credentials are separate secrets.

Storage is private and restricted by authorised membership, user folder and owned media metadata. Viewer URLs contain a random 256-bit token in the URL fragment; only its hash is stored. Every viewer refresh checks a server-side grant, owner, session, media scope, expiry and revocation before issuing 60-second media URLs. Already issued URLs can work until their short expiry. Permanent sheet cells never contain expiring storage URLs.

Garmin uses the official Personal API token exchange and activity list endpoint. Keys are backend-only. Stable external IDs deduplicate imports; matches to existing sessions are reviewed by the athlete, and imported source records do not create or double-count workouts automatically. Available metrics remain optional. No arbitrary API endpoint or URL is accepted from the client.

The initial account allow-list is `training_members`, populated only for the verified existing athlete account. RLS also checks ownership, so future members do not inherit access to another athlete. Coach accounts can later receive explicit relationships; public subscriptions, feeds, marketplaces and AI generation are out of scope.
